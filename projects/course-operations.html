POC / AI APPLICATION

公共文化课程运营智能助手

一个覆盖运营总览、课程规划、智能排课、招生监测和运营报告的 AI 应用原型。重点不是让模型“自动做一切”，而是把课程规划、排课规则、招生状态和人工决策串成可验证的业务闭环。

WorkflowAgentFastAPISQLite

业务问题

课程运营涉及课程规划、教师及教室资源协调、时段安排、招生状态跟踪等任务。多个环节依赖运营人员经验，容易出现信息分散、方案难比较的问题。

我的原型尝试

原型围绕“课程规划 → 智能排课 → 招生监测 → 运营报告”组织功能。智能排课按照约束排查冲突，给出最多三套候选方案；招生监测则根据约定阈值提醒运营人员关注异常。

技术与设计取舍

原型使用 FastAPI 与 SQLite 支撑业务数据，通过 Agent 和确定性 Workflow 组合处理任务：规则明确的环节优先固化流程，语言理解和报告表达再调用大模型。

核心功能

  • 运营总览：课程数、开班状态、招生风险和热门课程。
  • AI 课程规划：支持自然语言需求和资料输入，生成规划建议。
  • 智能排课：校验教师、场地、时间等硬约束，结合软偏好提供最多三套方案。
  • 招生监测：根据报名人数、开班门槛、容量和截止日期识别风险。
  • 运营报告：按周期汇总运营数据，辅助生成分析报告并导出。

技术架构与搭建框架

前端：HTML、CSS、JavaScript，负责业务页面、交互与结果展示。

后端：Python + FastAPI，提供业务接口、规则校验和数据服务。

数据库：SQLite，管理课程、教师、场地与招生演示数据。

AI 层：Dify 结合 Agent / Workflow，承担自然语言理解、规划辅助和部分分析生成工作。

架构路径：用户界面 → HTTP API → FastAPI 业务服务 → SQLite 业务数据／Dify AI 工作流。硬性规则由后端确定性逻辑校验，AI 辅助处理自然语言和软偏好，结果供运营人员最终确认。

实现路径

  1. 梳理运营流程，明确业务目标、数据输入和资源约束。
  2. 搭建课程、师资、教室等数据结构与后端规则。
  3. 设计 Agent / Workflow，区分确定性校验与 AI 处理环节。
  4. 实现前后端接口联动，测试排课冲突、招生预警与报告链路。
  5. 部署公开 POC 并根据操作反馈迭代。

在线体验

项目已部署为可访问的个人 POC。首次访问 Render 服务可能需要等待启动，页面使用演示数据。
