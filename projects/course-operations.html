02 / BUSINESS CONTEXT

业务问题

课程运营涉及课程安排、师资场地资源协调、招生跟踪和周期性复盘。信息分散、约束多、人工反复比对，是这个 POC 尝试解决的实际问题。

01

规划决策

结合运营历史、居民需求和课程资源形成规划思路。

02

排课协调

协调教师、场地和时间，并检查冲突与资源限制。

03

运营复盘

追踪招生风险、识别热门课程并生成周期报告。

03 / KEY FEATURES

五个业务模块

01 / DASHBOARD

运营总览

集中查看本期课程、开班情况、招生风险和热门课程。

02 / PLANNING

AI 课程规划

结合自然语言要求、参考资料和课程运营数据辅助形成规划建议。

03 / SCHEDULING

智能排课

校验教师、场地和时段等硬约束，结合软偏好给出最多三套候选方案。

04 / ENROLLMENT

招生监测

按照报名人数、开班门槛与截止日期识别风险并提示处理。

05 / REPORTING

运营报告

按选定周期汇总运营表现，生成分析内容并支持导出。

04 / DESIGN DECISIONS

为什么这样设计？

RULES FIRST

确定的业务约束交给规则

例如教师时间冲突、教室资源与人数限制，应由后端逻辑校验，而不是靠大模型猜测。

AI WHERE IT HELPS

非结构化问题由 AI 辅助

例如理解自然语言需求、分析课程偏好、形成运营建议，适合在工作流中使用模型能力。

05 / BUILD & VALIDATE

搭建与验证路径

  1. 业务访谈与流程拆解，明确运营人员、输入数据和目标。
  2. 设计课程、师资、场地等数据结构和业务规则。
  3. 实现 FastAPI 接口与前端操作，接入 Dify 的 AI 流程。
  4. 用排课冲突、招生预警等样例验证关键链路并迭代。
